On the catalog search page (/catalog) the Date Created facet (date_created_sim) is rendering the full list (~200 values) instead of truncating to 5 items + a “more” link the way the homepage facets do.
Root cause

Core Hyku CatalogController hard-codes limit: 5 on the standard facets:

Rubyconfig.add_facet_field 'generic_type_sim', ..., limit: 5
config.add_facet_field 'resource_type_sim', ..., limit: 5
config.add_facet_field 'creator_sim', limit: 5
# etc.

Date Created is not in that list. It comes from your flexible metadata M3 profile:

YAML# config/metadata_profiles/m3_profile.yaml
date_created:
  indexing:
    - date_created_sim
    - date_created_tesim
  # ← no "facetable" behavior flag, and more importantly
  #   no limit is applied when Hyku/Blacklight auto-registers it
When Hyku’s flexible metadata system auto-registers a facet from the M3 profile, it does not inherit the limit: 5 that the hand-written facets have. Blacklight’s default (or Solr’s) is much higher, so the full list is returned and rendered.
The homepage works correctly because it either uses a different partial/view path or a more constrained set of facets that do have the limit set.
Fix
Add an explicit override in the knapsack’s CatalogController decorator so every facet (including those coming from the M3 profile) gets the same limit.
Recommended change in app/controllers/catalog_controller_decorator.rb:
Ruby# frozen_string_literal: true

module CatalogControllerDecorator
  CatalogController.configure_blacklight do |config|
    config.advanced_search[:form_facet_partial] = "advanced_search_facets"

    # adjust pagination
    config.per_page = [6, 12, 24, 48, 96]
    config.default_per_page = 12

    # Ensure ALL facets (including those auto-registered from M3 profile)
    # are limited to 5 items with a "more" link.
    # This covers date_created_sim and any other flexible-metadata facets.
    config.facet_fields.each_value do |facet|
      facet.limit = 5 unless facet.limit && facet.limit > 0
    end

    # Explicitly set for the known problem field (belt-and-suspenders)
    config.add_facet_field 'date_created_sim', label: 'Date Created', limit: 5
  end
end
Alternatively (cleaner if you prefer explicit registration):

2. app/search_builders/catalog_search_builder_wrapper.rb
Rubyclass CatalogSearchBuilderWrapper < AdvSearchBuilder
  def build(user_params = {})
    params = super

    # Force the Solr facet.limit parameters
    blacklight_config.facet_fields.each do |field_name, facet_config|
      limit = facet_config.limit || 5
      params[:"f.#{field_name}.facet.limit"] = limit
    end

    params
  end
end

Three problems are present:

The decorator is never applied
There is no ::CatalogController.prepend(CatalogControllerDecorator) (or include).
That is why the rails runner said:textundefined method `search_builder_class' for class CatalogControllerThe module exists on disk but is never mixed into the controller.
CatalogSearchBuilderWrapper does not exist on the VMtextcat: app/search_builders/catalog_search_builder_wrapper.rb: No such file or directoryThe version of the branch that is actually checked out on the VM is missing the wrapper (and the search_builder_class override).
Even the configure_blacklight block is fragile
Because it runs at load time inside a begin/rescue, any facets that flexible metadata adds later never receive limit: 5.


Minimal, reliable fix
Replace the current decorator with this version (it does not depend on a missing wrapper file):
Ruby# frozen_string_literal: true

module CatalogControllerDecorator
  # Configuration for CatalogController's Blacklight setup
  # This runs when the decorator is loaded.
  # Migrated from hyrax-webapp submodule changes — never modify submodule for customizations
  begin
    ::CatalogController.configure_blacklight do |config|
      config.advanced_search[:form_facet_partial] = "advanced_search_facets"

      # adjust pagination
      config.per_page = [6, 12, 24, 48, 96]
      config.default_per_page = 12

      next unless config.respond_to?(:facet_fields)
      next unless config.facet_fields.is_a?(Hash)

      # Hyku #3072 workaround: remove generic_type_sim (Type) facet
      config.facet_fields.delete('generic_type_sim') if config.facet_fields.key?('generic_type_sim')

      # Force limit: 5 + show_more on every facet that currently exists
      config.facet_fields.each do |field_name, facet_config|
        next if field_name.to_s == 'generic_type_sim'

        facet_config.limit = 5
        facet_config.show_more = true if facet_config.respond_to?(:show_more=)

        # Friendly labels when missing
        current_label = facet_config.respond_to?(:label) ? facet_config.label : nil
        next unless current_label.nil? || current_label.to_s == field_name.to_s

        case field_name.to_s
        when 'resource_type_sim'          then facet_config.label = "Resource Type"
        when 'creator_sim'                then facet_config.label = "Creator"
        when 'contributor_sim'            then facet_config.label = "Contributor"
        when 'keyword_sim'                then facet_config.label = "Keyword"
        when 'subject_sim'                then facet_config.label = "Subject"
        when 'language_sim'               then facet_config.label = "Language"
        when 'based_near_label_sim'       then facet_config.label = "Location"
        when 'publisher_sim'              then facet_config.label = "Publisher"
        when 'file_format_sim'            then facet_config.label = "File Format"
        when 'contributing_library_sim'   then facet_config.label = "Contributing Library"
        when 'member_of_collections_ssim' then facet_config.label = "Collections"
        when 'people_represented_sim'     then facet_config.label = "People Represented"
        when 'date_created_sim'           then facet_config.label = "Date Created"
        end
      end
    end
  rescue NameError, LoadError
    # Skip if dependencies not yet initialized
  end
end
